# train-oomawari

JR東日本の東京近郊区間を対象に、指定した2駅間で「同じ駅を2回通らない」最大営業キロ経路を探索するプログラムです。

## 現在の構成

- 出発駅・到着駅は GitHub Actions のプルダウンから選択
- 704駅を選択肢として登録
- 実行時の鉄道データは data/tokyo_near_zone.csv を使用
- 実行時に外部APIへアクセスしない
- 探索は SciPy / HiGHS の MILP を使った厳密解を求める方式
- 結果は Actions の omawari-result artifact に保存
- GitHub Actions の「Run workflow」から実行

## 使い方

GitHub の Actions → Omawari route → Run workflow を開き、出発駅と到着駅をプルダウンから選択して Run workflow を押します。

実行後、omawari-result artifact に最大経路と各区間が出力されます。

現在の既定値は 東京 → 新宿です。

## 探索モデル

現在の実装では、鉄道区間を無向グラフの辺として扱い、出発駅は1本の辺から出る、到着駅は1本の辺から入る、途中駅は1本ずつ入って1本ずつ出る、同じ駅を2回使用しない、選択された全駅が1本の出発駅→到着駅の経路につながる、という制約で営業キロの総和を最大化しています。

MILP の最適化が optimal となった場合、そのデータセットとモデルに対する最大値です。

## JR東日本の制度との関係

JR東日本は大都市近郊区間内相互発着の普通乗車券について、実際に乗車する経路とは異なる経路を選択できる制度を定めています。また、JR東日本の「東京付近の特定区間を通過する場合の特例」では、太線区間について「後戻りしたり再度同じ駅を通らない」ことが条件として明記されています。

ただし、ここで使用しているCSVは鉄道網を表すデータであり、営業規則そのものではありません。乗車可否・運賃計算の最終判断は、JR東日本の現行の旅客営業規則・運賃計算規則を優先します。

## データ

data/tokyo_near_zone.csv はリポジトリ内に固定保存しています。実行時に外部通信を行わないため、同じ入力と同じデータなら同じ探索対象になります。データ更新時にはJR東日本の現行路線・営業キロ・営業規則との照合が必要です。

## 公開サイト

GitHub Pages に、駅名を入力して検索できるWeb画面を追加しています。

- 駅名は五十音順の読みを付けて検索・選択
- 部分一致検索に対応
- 「最大経路を計算」を押すと、Pyodide + SciPy により利用者のブラウザ内でMILPを実行
- 計算サーバーを共有しないため、多数の利用者が同時に使える構成
- 鉄道データはリポジトリ内のCSVをサイトへ同梱

GitHub Pages の公開元は **Settings → Pages → Build and deployment → Source: GitHub Actions** に設定します。GitHub Pages は静的ファイルを公開する仕組みで、サーバー側のPythonは実行できないため、最適化処理をブラウザ側へ移しています。GitHubの公式ドキュメントでも、GitHub Actionsを公開元として設定できることが案内されています。
